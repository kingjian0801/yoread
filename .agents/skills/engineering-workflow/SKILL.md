# Matt 工程工作流

项目规则及用户当前要求优先。先读取 AGENTS.md/CLAUDE.md、涉及代码及检查命令，核对实际工作区、版本、分支和未提交内容。此入口只选择适用技能，不增加常驻服务、强制状态机或审批。

- 明确的小改动直接实现并验证；较大需求用 `grilling` 澄清，再按 `docs/agents/issue-tracker.md` 使用 `to-spec`、`to-tickets`、`implement-spec`。同一任务只保留一份规格和任务记录，不自动创建远端工单。
- 在约定的公开边界使用 `tdd`，实际观察失败，再做最小实现。排障用 `diagnosing-bugs` 建立可复现信号后验证假设；架构、术语或设计取舍按需用 `codebase-design`、`domain-modeling`。
- 在实际目标工作区运行项目适用测试、静态检查及构建；对照规格验收。用 `code-review` 分别审查规范与需求，指定明确基线、规格和所有本次未提交/新增文件；空提交 diff 不能代替工作区审查。
- `pr` 只在既有项目授权内整理并提交；推送、MR、合并和部署分别遵守项目规则。读取同一候选最新 CI，不能拿旧绿灯或健康检查代替业务验收。
- 任务记录填写实际验证与限制，只有完成的项才标记完成。反馈形成后续任务；需要时使用 `handoff`、`retro`，不要求每次小改动都写复盘或新增规则。

按当前客户端列出的技能名调用；原生插件可能显示 `engineering-workflow:<技能名>`，项目技能可能无前缀。不要重复加载同一包。使用说明见项目 `docs/agents/workflow.md`；没有该文档时遵守当前项目既有约定。此包不扩展外部操作权限，不自带部署凭据。
