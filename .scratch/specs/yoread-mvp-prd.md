# Yoread 网页翻译扩展首版产品需求文档

**版本** v1.0 · **状态** 已定稿，待 PR 评审 · **日期** 2026-11-19

**目标项目** `kingjian0801/yoread` · **首版交付** 桌面 Chrome 本地安装试用版

## 1. 问题与目标

阅读英文新闻、文档或博客时，用户希望在当前网页直接看到中文译文，并能随时切回原文。使用 GitHub 时，用户也希望菜单、按钮和状态等固定界面词条有一致的中文表达，同时保留仓库名、用户名和代码等原始信息。

首版让 Kim 和 Coco 各自用自己的 DeepSeek API Key，完成从安装、配置到翻译、恢复的完整流程。网页翻译覆盖 Chrome 允许扩展访问的普通 HTTP(S) 页面，首版验收语言为英文译为简体中文。GitHub 专用汉化作为独立功能交付。

## 2. 产品方案

| 能力 | 首版交付 |
| --- | --- |
| 安装与配置 | 提供可在桌面 Chrome 本地加载的扩展和试用指南。用户可填写、测试、更换和清除自己的 DeepSeek API Key。 |
| 页面翻译 | 用户点击「翻译此页」手动触发，将当前主页面中已加载的可读英文文本译为简体中文。译文显示在原页面，保留原有链接、图片、表格和交互结构。 |
| 确认发送 | 每个页面首次向 DeepSeek 发送正文前，用户必须确认。公开网页和登录后可见的网页均适用。 |
| 取消与恢复 | 「恢复原文」撤销当前页面上通用翻译产生的改动，进行中的请求也会失效。 |
| GitHub 专用汉化 | 提供独立开关，直接复用上游 GitHub 汉化词库和相关规则，按 GPL-3.0 处理。从仓库主页、Issue 和 PR 的常用界面开始验收。 |
| 错误反馈 | 显示配置缺失、页面受限、无可翻译内容、翻译中、完成、部分完成及失败等结果，并给出相应操作。 |

## 3. 用户故事

1. 作为试用者，我希望按指南在一台新的桌面 Chrome 中安装 Yoread，以便独立开始试用。
2. 作为试用者，我希望配置并测试自己的 DeepSeek Key，以便在开始翻译前确认服务可用。
3. 作为试用者，我希望更换或清除 Key，以便处理过期凭据或停止使用。
4. 作为网页读者，我希望手动翻译当前页面，以便只处理我选定的网页。
5. 作为网页读者，我希望每个页面首次发送正文前看到接收方和发送范围，以便决定是否继续。
6. 作为网页读者，我希望拒绝发送后能继续阅读原文，以便保留对页面内容的控制。
7. 作为网页读者，我希望译文留在原页面，并保留链接、图片和表格，以便继续阅读和操作。
8. 作为技术文档读者，我希望代码、命令和输入内容保留原样，以便复制和使用。
9. 作为网页读者，我希望取消进行中的翻译或恢复原文，以便随时回到原页面。
10. 作为网页读者，我希望能翻译随后加载的文章段落，以便读完动态页面。
11. 作为网页读者，我希望在服务限流、余额不足或超时时看到具体提示，以便判断应等待、调整配置还是重试。
12. 作为 GitHub 用户，我希望单独控制界面汉化，以便在阅读译文的同时保留习惯的界面语言。
13. 作为 GitHub 用户，我希望恢复 Issue 或 PR 正文原文时保留已经开启的界面汉化，以便两项功能可以分别使用。
14. 作为评审者，我希望有可重复的页面样本和真实试用记录，以便判断首版是否达标。

## 4. 实现决策

### 页面范围与交互

- Chrome 扩展按用户操作取得当前标签页访问权限。浏览器设置页等扩展无法访问的页面显示提示。翻译范围为主页面中已加载且可读取的可见文本，跨源嵌入页面、图片文字、PDF 和浏览器内部页面留待后续评估。[Chrome 扩展权限文档](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)
- 界面展示「翻译此页」「翻译中」「恢复原文」和出错后的重试入口。同一页面进行中的重复点击合并为一次操作。没有可处理文本时显示提示，页面保持原样。
- 翻译只替换可读文本，保留链接目标、事件处理、媒体及网页结构。代码、命令、表单值、编辑区和隐藏内容排除在提取范围外。试用版对动态新增内容采用再次点击翻译的方式，已翻译段落不重复提交。
- 每次翻译绑定当前标签页和页面。刷新、关闭、导航或恢复后，旧请求即使返回也不得写回页面。恢复时只撤销扩展对仍存在文本的改动，网页自身的后续更新照常保留。

### DeepSeek 与发送确认

- 仅接入 DeepSeek 官方 API，由扩展直接发送 HTTPS 请求，使用用户配置的 Key。具体模型在实现时从官方可用模型中确定，并在试用说明中记录。扩展设置提供连接测试，测试请求使用固定短文本。[DeepSeek API 文档](https://api-docs.deepseek.com/)
- 每个标签页中的页面首次向 DeepSeek 发送正文之前，展示确认提示。提示写明接收方为 DeepSeek、发送范围为当前页识别出的可翻译正文，并提供取消入口。当用户取消、关闭提示或未作选择时，不发送正文请求。同一页面后续手动翻译可沿用该次确认。刷新、跳到另一页或标签关闭后重置确认。此规则也覆盖扩展无法判断登录状态的页面。
- 请求只包含翻译指令和所需文本。网页地址、Cookie、表单值及浏览记录不作为额外请求字段。Key 仅保存在扩展本地设置中，不写入页面、同步存储或日志。网页正文和译文仅在完成本次操作所需期间保留，试用版不保存翻译历史。
- 将鉴权失败、余额不足、限流、服务异常和网络超时映射到可操作的提示。分批翻译时，失败批次保留原文，界面标记为部分完成，允许重新处理失败段落。所有已应用译文都可一并恢复。[DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/)

### GitHub 专用汉化与上游复用

- 采用独立的「GitHub 界面汉化」开关。启用后匹配约定的菜单、按钮和状态标签，切换仓库、Issue 和 PR 后仍能处理新界面。仓库名、用户名、分支名、提交哈希及代码保持原样。
- GitHub 专用汉化在本地应用词库和规则。通用翻译应跳过专用汉化接管的固定界面区域。恢复通用翻译时正文恢复原文，专用汉化保持原状。关闭专用汉化时，仅撤销它对界面的改动。
- 引入 `maboloshi/github-chinese` 的专用词库和相关规则时，锁定上游提交，保留版权和来源记录，记录修改内容，并按 GPL-3.0 准备派生版许可及对应源码。当前 Yoread 仓库使用 MIT，代码引入时须一并落实派生版的许可标识与分发安排。[上游源码](https://github.com/maboloshi/github-chinese/tree/gh-pages) · [上游许可证](https://github.com/maboloshi/github-chinese/blob/gh-pages/LICENSE)

## 5. 验证与验收

自动化测试从扩展的用户入口验证页面行为。使用固定网页和可控的 DeepSeek 响应，检查用户操作、网络请求和最终页面状态。参考上游对动态导航、代码与输入框跳过、用户标识保留等行为的测试。真实试用由 Kim 与 Coco 在桌面 Chrome 中各自完成，使用自己的 Key。[上游测试目录](https://github.com/maboloshi/github-chinese/tree/gh-pages/test)

| 验收场景 | 通过标准 | 证据 |
| --- | --- | --- |
| 首次安装 | 两人分别加载扩展，设置自己的 Key，测试连接并完成第一次翻译 | 两份试用记录 |
| 跨网站翻译 | 新闻、技术文档和博客各一页可从同一入口手动翻译为简体中文并恢复 | 记录所用页面与结果 |
| 页面首次发送 | 公开页面和登录后的页面首次翻译均出现发送确认。取消、关闭提示或未选择时，捕获到零次正文请求。确认后只发送约定范围的文本 | 公开及登录态样本与网络断言 |
| 确认有效范围 | 同一页面再次手动翻译可沿用确认。刷新、切换页面或重新打开标签后，首次发送前再次提示 | 导航、刷新与请求断言 |
| 页面完整性 | 带链接、图片、表格、代码块和表单的页面翻译后，链接仍可点击，代码和输入值保持原样 | 页面回归测试 |
| 恢复与导航 | 翻译进行中恢复原文，或切到另一页后旧响应返回，页面均保持正确状态。再次翻译可正常开始 | 延迟响应与导航测试 |
| GitHub 汉化 | 仓库首页、Issue 和 PR 的约定词条正确显示。恢复正文不撤销界面汉化，关闭汉化仅撤销界面翻译 | GitHub 样本与真实浏览器记录 |
| 错误及部分失败 | 无效 Key、余额不足、限流、超时和部分失败提供相应提示。原文可读，已应用译文可恢复 | 模拟响应和状态断言 |
| 数据边界 | 安装后浏览网页、拒绝发送、启用专用汉化时均不会产生正文请求。请求正文不含表单值，日志不含 Key 或正文 | 请求截获与日志检查 |
| 许可交付 | 分发包和对应源码保留上游来源、许可及修改说明，记录复用的上游提交 | 分发前评审核对 |

在现有 PR CI 中加入扩展构建和上述自动化检查。真实 DeepSeek 请求由试用者在本地执行，CI 用模拟响应。Kim 核对构建、权限、请求与恢复行为，Coco 核对安装流程、译文可读性及试用场景。双方记录样本、扩展版本和结果后确认首版是否通过。

## 6. 后续范围

手机端、其他桌面浏览器、Chrome 网上应用店上架、划词翻译、双语对照、按站点自动翻译、更多语言的正式验收和跨设备同步留待后续版本。试用版采用本地安装交付。

## 7. 评审时确认的细节

- 对照一个实际仓库确认 GitHub 第一批必验词条，并确认开关的初始状态和启用方式。
- 选定本次试用的 DeepSeek 模型、三类公开页面样本和可用于验证登录场景的非敏感样本。
- 确认以「扩展用户入口的自动化回归」和「Kim 与 Coco 的真实 Chrome 试用」作为验收边界。验收表中的证据在实现后填写。
